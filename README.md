# AU-Getway

মার্চেন্ট পেমেন্ট ডেস্ক। দোকানের অর্ডারের জন্য চেকআউট লিংক বানানো, বিকাশ/নগদ/রকেট/উপায়ের পেমেন্ট SMS দেখে নিজে থেকে যাচাই করা, ইনভয়েস, পেমেন্ট লিংক, API key, আর নিজের Android ফোন দিয়ে ওয়েবসাইট থেকে SMS পাঠানো, সব এক জায়গায়। ডাটাবেস VPS-এর নিজের PostgreSQL।

| | |
| --- | --- |
| ওয়েবসাইট | https://pay.uniqbd.com |
| API | https://api.uniqbd.com/api |
| কোড | https://github.com/SohelOnlineit/AUGetway |
| সার্ভারে কোডের ফোল্ডার | `/var/www/pay.uniqbd.com` |
| সার্ভিস | `uniqpay-api` (`127.0.0.1:4100`), `uniqpay-web` (`127.0.0.1:3100`) |
| ডাটাবেস | PostgreSQL 18, ইউজার `uniqpay`, `127.0.0.1:5432` |

## কী কী আছে

**পেমেন্ট**
- চেকআউট পেজ (`/pay/…`): কাস্টমার মেথড বেছে পেমেন্ট করে, ট্রানজেকশন আইডি দিয়ে যাচাই করে।
- যাচাইয়ের তিন উপায়: ট্রানজেকশন আইডি, সেন্ডার নম্বর, ইউনিক অ্যামাউন্ট। মেলে ফোনে আসা আসল পেমেন্ট SMS-এর সাথে।
- ব্যালেন্স মিলানো (ঐচ্ছিক): SMS-এর ব্যালেন্স সেভ করা ব্যালেন্স + পেমেন্টের সমান না হলে অটো-অ্যাপ্রুভ হয় না।
- ইনভয়েস (`/bill/…`) ও পেমেন্ট লিংক (`/l/…`, কাস্টম ফিল্ড, পরিমাণ, মেয়াদ সহ)।
- সরকারি গেটওয়ের সেটিংস (bKash, Nagad, Rocket, Upay, BanglaQR) এবং ম্যানুয়াল মেথড (চার্জ, ডিসকাউন্ট, সীমা, QR, টলারেন্স)।
- মার্চেন্ট API: Uddokta Pay-সামঞ্জস্যপূর্ণ (`checkout-v2`, `verify-payment`) এবং `v1/checkouts`। পেমেন্ট হলে webhook যায়।

**SMS গেটওয়ে (Android ফোন)**
- ফোন অ্যাপে ব্যাংক/ওয়ালেটের পেমেন্ট SMS নিজে থেকে ডেস্কে আসে। OTP আর ব্যক্তিগত নম্বরের মেসেজ বাদ যায়।
- ডেস্ক থেকে বা API দিয়ে (`POST /api/sms/send`) ফোনের সিম দিয়ে SMS পাঠানো যায়। ফোন অফলাইন থাকলে সঙ্গে সঙ্গে পরিষ্কার এরর আসে।
- একাধিক ফোন, সিম স্লট বাছা, ফোনের ব্যাটারি ও শেষ দেখার সময়।

**ডেস্ক (অ্যাডমিন)**
- ড্যাশবোর্ড, লেনদেন, কাস্টমার, রিপোর্ট, ব্র্যান্ড ও সিস্টেম সেটিংস, অ্যাডমিন অ্যাকাউন্ট।
- Security Monitoring: সন্দেহজনক সেন্ডার, একই ট্রানজেকশন আইডি বারবার, SMS-এর ঢল ইত্যাদির লগ।
- **ব্যাকআপ** (`/admin/backups`): প্রতিদিন ভোর ৫টায় ডাটাবেসের কপি, ৬০ দিন রাখা হয়।
- **Cloudflare Turnstile** (Security Monitoring পেজ): লগইন ও পাবলিক পেমেন্ট পেজে বট ঠেকানো।

## নিজের কম্পিউটারে চালানো

দরকার: Node 20.19+ (22 ভালো), pnpm 9.15 (`corepack enable`)।

```bash
pnpm install
```

```bash
cp .env.example .env
```

`.env`-এ অন্তত `JWT_SECRET` (৩২+ অক্ষর) আর `ADMIN_PASSWORD` বদলান। ডাটাবেসের জন্য এমবেডেড PostgreSQL চালু করুন (আলাদা টার্মিনালে খোলা রাখুন):

```bash
pnpm db:local
```

```bash
pnpm db:push
```

```bash
pnpm dev
```

ওয়েব http://127.0.0.1:3100 আর API http://127.0.0.1:4100/api। প্রথমবার API চালু হলে `ADMIN_EMAIL` আর `ADMIN_PASSWORD` দিয়ে মূল অ্যাডমিন বানায়। সেই ইমেইলে `/au` পেজ থেকে ঢুকুন।

### এনভায়রনমেন্ট ভ্যারিয়েবল

| নাম | কাজ |
| --- | --- |
| `NODE_ENV` | সার্ভারে `production` |
| `PORT` | API পোর্ট (`4100`) |
| `WEB_ORIGIN` | ওয়েবসাইটের ঠিকানা (CORS)। কমা দিয়ে একাধিক |
| `API_PUBLIC_URL`, `NEXT_PUBLIC_API_URL` | ব্রাউজার ও ফোন যে API ঠিকানা ব্যবহার করে |
| `DATABASE_URL` | PostgreSQL সংযোগ |
| `JWT_SECRET` | লগইন টোকেনের গোপন কী। **৩২+ অক্ষর, না থাকলে সার্ভারে API চালুই হয় না** |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | প্রথমবারের মূল অ্যাডমিন |
| `INTERNAL_API_URL` | (ঐচ্ছিক) Next থেকে API-র ঠিকানা, ডিফল্ট `http://127.0.0.1:4100` |
| `TURNSTILE_OFF=1` | জরুরি: Turnstile আটকে দিলে বন্ধ করতে (নিচে দেখুন) |

আসল `.env` কখনো git-এ যায় না (`.gitignore`-এ আছে)।

## কাজ শেষে অটো পুশ

এই প্রজেক্টে AI সহকারী (Claude Code, Cursor) কোনো কাজ শেষ করলে নিজে থেকে কমিট করে https://github.com/SohelOnlineit/AUGetway.git-এ পুশ করে দেয়। প্রতিবার আলাদা করে বলতে হয় না। নিয়মটা [`CLAUDE.md`](./CLAUDE.md) আর [`.cursor/rules/push-when-done.mdc`](./.cursor/rules/push-when-done.mdc) ফাইলে লেখা আছে, সহকারী এগুলো নিজে পড়ে।

- কাজ পরীক্ষা করে (টাইপচেক, টেস্ট) তারপর পুশ করে। কাজ অর্ধেক থাকলে বা পরীক্ষা ফেল করলে পুশ করে না, কারণ জানায়।
- গোপন জিনিস (`.env`, পাসওয়ার্ড, token, ব্যাকআপ `.sql`, `.apk`) কখনো কমিট হয় না।
- জোর করে পুশ (force-push) বা ইতিহাস বদলানো করে না। পুশ আটকে গেলে (GitHub-এ নতুন কমিট থাকলে) নিজে রিবেস করে, কনফ্লিক্ট হলে থেমে আপনাকে জানায়।
- শুধু ওই একটাই রিমোটে পুশ করে। `origin` অন্য ঠিকানায় থাকলে পুশ করে না।
- **পুশ মানে লাইভ সাইট আপডেট নয়।** পুশের পর লাইভ সার্ভারে আপডেট করতে নিচের কমান্ড চালাতে হয়।

বন্ধ করতে চাইলে `CLAUDE.md` ও `.cursor/rules/push-when-done.mdc` থেকে এই অংশ মুছে দিন।

## লাইভ সার্ভার আপডেট করা

কম্পিউটারে কোড বদলে GitHub-এ পুশ করার পর, সার্ভারে SSH করে **এই একটা কমান্ডই** চালান:

```bash
sudo bash /var/www/pay.uniqbd.com/deploy/ubuntu/update.sh
```

এটা নতুন কোড আনে, প্যাকেজ ইনস্টল করে, ডাটাবেসে নতুন টেবিল/কলাম যোগ করে (কিছু মোছে না), বিল্ড করে, দুটো সার্ভিস রিস্টার্ট করে এবং `verify-live: OK` দিয়ে চেক করে। `.env`, ডাটাবেসের ডেটা আর `backups` ছোঁয় না। GitHub পাসওয়ার্ড চাইলে ইউজারনেম `sohelonlineit` আর পাসওয়ার্ডের জায়গায় GitHub token দিন।

**রিপোজিটরি সরানোর পর প্রথমবার:** সার্ভারের কোডের ইতিহাস GitHub-এর নতুন রিপোর সাথে মেলে না, তাই স্ক্রিপ্ট থেমে একটা কমান্ড দেখাবে। সার্ভারে কোডে নিজে এডিট না থাকলে সেটা একবার চালিয়ে আবার `update.sh`:

```bash
sudo git -c safe.directory=/var/www/pay.uniqbd.com -C /var/www/pay.uniqbd.com reset --hard origin/main
```

পুরো সার্ভার সেটআপ (নতুন VPS-এ), nginx, রোলব্যাক ও সমস্যার সমাধান: [`deploy/ubuntu/README.md`](./deploy/ubuntu/README.md)

## Cloudflare Turnstile

বট ঠেকাতে ডেস্ক লগইন এবং পাবলিক পেমেন্ট পেজে (পেমেন্ট লিংক, বিল, ট্রানজেকশন আইডি যাচাই) চালানো যায়। ফোন অ্যাপের লগইনে এটা চায় না।
1. Cloudflare-এ Turnstile widget বানান, Domain-এ `pay.uniqbd.com`।
2. ডেস্কে **Security Monitoring** পেজের **Cloudflare Turnstile** কার্ডে Site key ও Secret key বসিয়ে **Save keys**।
3. কার্ডের চেক সলভ করে **Test and turn on**। টেস্ট পাশ না করলে চালু হয় না, তাই ভুল key দিয়ে লগইন বন্ধ হয়ে যায় না।
4. key বদলালে চেক নিজে বন্ধ হয়। **Turn off** দিলে key সেভ থাকে।

লগইন আটকে গেলে: সার্ভারের `.env`-এ `TURNSTILE_OFF=1` লিখে `sudo systemctl restart uniqpay-api`। ঢুকে ঠিক করে লাইনটা মুছে আবার রিস্টার্ট দিন।

## দুই-ধাপ লগইন (অথেন্টিকেটর কোড)

পাসওয়ার্ড চুরি বা আন্দাজ হয়ে গেলেও যেন কেউ ঢুকতে না পারে। ডিফল্টে বন্ধ। প্রতিটি অ্যাডমিন নিজের অ্যাকাউন্টে নিজে চালু করে। মূল অ্যাডমিনের জন্য জোর সুপারিশ।
1. ডেস্কের **Account** পেজে **Two-factor sign-in** কার্ডে বর্তমান পাসওয়ার্ড দিয়ে **Set up**।
2. Google Authenticator, Authy বা Microsoft Authenticator-এ **Enter a setup key** (time based) দিয়ে দেখানো key বসান।
3. অ্যাপের ৬ অঙ্কের কোড লিখে **Turn on**।

এরপর ওয়েবে ও ফোন অ্যাপে লগইনে পাসওয়ার্ডের পর কোড চায়। একই কোড দুইবার চলে না। ভুল কোড ভুল পাসওয়ার্ডের মতো গোনা হয়। বন্ধ করতে পাসওয়ার্ড ও নতুন কোড দুটোই লাগে, তাই চুরি যাওয়া লগইন টোকেন দিয়ে এটা বন্ধ করা যায় না। চালু করলে আগে থেকে লগইন থাকা ফোন/ব্রাউজার বের হয়ে যায় না।

**আগে ফোন অ্যাপ আপডেট করুন।** কোড লেখার ঘর শুধু অ্যাপ ২.৩১ বা নতুনে আছে। পুরোনো অ্যাপে নতুন করে লগইন করা যাবে না (আগের লগইন চলতে থাকে)। নতুন APK: `git tag apk-v2.31 && git push origin apk-v2.31`, তারপর GitHub Releases থেকে নামিয়ে ফোনে ইনস্টল করে লগইন চেক করুন। তারপর 2FA চালু করুন।

ফোন হারালে বা অ্যাপ মুছলে: সার্ভারের `.env`-এ `TWO_FACTOR_OFF=1` লিখে `sudo systemctl restart uniqpay-api`। পাসওয়ার্ড দিয়ে ঢুকে Account পেজে 2FA নতুন করে সেট করুন, তারপর লাইনটা মুছে আবার রিস্টার্ট দিন। এই লাইন থাকলে কারও জন্যই কোড চাওয়া হয় না, তাই কাজ শেষে অবশ্যই মুছুন (`audit-server.sh` মনে করিয়ে দেয়)।

## ফোন অ্যাপ (Android)

`apps/mobile`। সাইন-ইন করে ডেস্কের ইমেইল ও পাসওয়ার্ড দিয়ে। অ্যাপ নিজেই `https://api.uniqbd.com/api`-এ কথা বলে।
- প্রথমবার **SMS পড়া, SMS পাঠানো, ফোন স্টেট** পারমিশন দিন, আর ব্যাটারি অপটিমাইজেশনে "Unrestricted"। নইলে ফোন স্ক্রিন বন্ধ করলে Android অ্যাপ থামিয়ে দিতে পারে এবং ওয়েবসাইটের SMS আটকে থাকে।
- নোটিফিকেশনে "AU-Getway · Online" দেখা গেলে ফোন জুড়ে আছে। সমস্যা হলে সেখানে লাল বার্তা আসে।
- বিল্ড (Android SDK লাগে): `pnpm install` তারপর `pnpm --filter @uniqpay/mobile android`। `.apk` ফাইল git-এ যায় না।

## API ব্যবহার (মার্চেন্টের সাইট থেকে)

ডেস্কে **Api Keys** থেকে key বানান। তারপর:

| মেথড | পাথ | কাজ |
| --- | --- | --- |
| POST | `/api/checkout-v2` | Uddokta Pay-র মতো চেকআউট। হেডার `RT-UDDOKTAPAY-API-KEY` |
| POST | `/api/verify-payment` | পেমেন্ট যাচাই। বডি `invoice_id` |
| POST | `/api/v1/checkouts` | চেকআউট বানানো। হেডার `x-merchant-key` |
| GET | `/api/v1/checkouts/:id` | চেকআউটের অবস্থা |
| POST | `/api/sms/send` | ফোন দিয়ে SMS (key-এ `sms:send` দরকার) |

বিস্তারিত তালিকা ডেস্কের **API References** পেজে।

## নিরাপত্তার নোট

- ভুল পাসওয়ার্ডের সীমা (১৫ মিনিটে, ৪২৯ ফেরত দেয়): একই ইমেইল ও একই আইপি থেকে ৮ বার; এক আইপি থেকে সব ইমেইল মিলিয়ে ৩০ বার; এক অ্যাকাউন্টে সব আইপি মিলিয়ে ৬০ বার। অ্যাকাউন্ট পেজে "বর্তমান পাসওয়ার্ড" যাচাইয়েও একই সীমা। একজনের ভুল চেষ্টায় আসল অ্যাডমিন অন্য আইপি থেকে আটকায় না।
- ডেস্কের ওয়েব লগইন ৭ দিন চলে, তারপর আবার ঢুকতে হয়। ফোন অ্যাপের টোকেন ৫ বছর, কারণ ব্যাকগ্রাউন্ডে ফোন নিজে আবার লগইন করতে পারে না। পাসওয়ার্ড বদলালে সব টোকেন (ফোনসহ) বাতিল হয়।
- নতুন পাসওয়ার্ড কমপক্ষে ১০ অক্ষর। পুরোনো ৮-৯ অক্ষরের পাসওয়ার্ডে লগইন চলে।
- সব রুটে আইপি-ভিত্তিক রেট লিমিট আছে (`apps/api/src/rate-limit.ts`): লগইন ১৫ মিনিটে ৩০, বিল/লিংক চালু করা মিনিটে ২০, পাবলিক পেমেন্ট ফর্ম মিনিটে ১২০, পাবলিক পেজ দেখা মিনিটে ১২০০ (চেকআউট পেজ ২ সেকেন্ডে একবার স্ট্যাটাস নেয়), মার্চেন্ট API key-র রুট মিনিটে ৬০০। বাংলাদেশের মোবাইল নেটওয়ার্কে অনেক গ্রাহক একই আইপি ভাগ করে, তাই পাবলিক সীমা বেশি রাখা।
- API ঠিক একটি proxy (nginx) বিশ্বাস করে (`trust proxy = 1`)। nginx যেন `X-Forwarded-For`-এ শুধু `$remote_addr` পাঠায় (`deploy/ubuntu/nginx-*-snippet.conf`)। না হলে ভিজিটর নিজের বানানো হেডার দিয়ে সীমা এড়াতে পারে। Cloudflare সামনে থাকলে nginx-এ `real_ip` সেট না করলে সবাই Cloudflare-এর আইপি হিসেবে গোনা হয়।
- JSON বডি সাধারণ রুটে ২৫৬ KB। শুধু ছবিসহ রুটে (পেমেন্ট মেথডের QR, লিংকের ছবি, সেটিংসের লোগো, রিসিপ্ট) ৩ MB।
- Webhook শুধু পাবলিক http/https ঠিকানায় যায়। ইন্টারনাল ঠিকানা (localhost, ১০.x, IPv6 রূপসহ) বন্ধ।
- API key ডাটাবেসে হ্যাশ করে রাখা হয়। নিজের দেওয়া (custom) key কমপক্ষে ১৬ অক্ষর।
- সব `/desk/*` রুটে লগইন লাগে এবং প্রতিটি কোয়েরি নিজের ডেস্কের ডেটায় সীমিত।
- ব্যাকআপ ও Turnstile সেটিংস শুধু মূল অ্যাডমিনের।
- পেইড (Success) ট্রানজেকশন মুছতে এবং **Delete all** চালাতে পারে শুধু মূল অ্যাডমিন। স্টাফ অ্যাকাউন্ট খোলা, ফেইল্ড ও মেয়াদ-শেষ ট্রানজেকশন মুছতে পারে। নইলে একজন স্টাফ পেমেন্টের হিসাব মুছে চুরি ঢাকতে পারত।
- রিপোর্টের "আজ/এই সপ্তাহ/এই মাস" এখন বাংলাদেশ সময় (UTC+6) ধরে। আগে সার্ভারের UTC ধরত, তাই রাত ১২টার পরের বিক্রি আগের দিনে যেত। API key-র মেয়াদও সেই দিনের শেষে (বাংলাদেশ সময়) শেষ হয়।
- ডেস্কের সেটিংসের পাসওয়ার্ড ও টোকেন (SMTP password, Telegram token, Meta token, webhook secret) আর অফিশিয়াল গেটওয়ের ক্রেডেনশিয়াল ডাটাবেসে এনক্রিপ্ট করে (AES-256-GCM) রাখা হয়। ডেস্কের সেটিংস পেজ এগুলো দেখায় `********` করে, আসল মান ব্রাউজারে যায় না। ফর্মে না ছুঁলে সেভ করলেও আসল মান থাকে। পুরোনো প্লেইন-টেক্সট মান API চালু হওয়ার সময় একবার এনক্রিপ্ট হয়ে যায়। কী আসে `.env`-এর `DATA_KEY` থেকে, না থাকলে `JWT_SECRET` থেকে। এর যেকোনো একটা বদলালে সেভ করা এই মানগুলো পড়া যায় না, আবার বসাতে হয়। তাই `JWT_SECRET` বদলানোর আগে মনে রাখুন।
- Webhook-এ সেটিংসের **Global Webhook Signing Secret** বসানো থাকলে দুটো হেডার যায়: `X-Webhook-Timestamp` (সেকেন্ড) আর `X-Webhook-Signature: sha256=<hex>`, যেখানে hex = `HMAC-SHA256(secret, timestamp + "." + body)`। দোকানের সার্ভার মিলিয়ে দেখবে, আর timestamp ৫ মিনিটের বেশি পুরোনো হলে নেবে না (নমুনা: `apps/api/src/webhook-sign.ts` এর `webhookIsGenuine`)। secret না থাকলে আগের মতোই সাইন ছাড়া যায়। যাই হোক, মাল পাঠানোর আগে `verify-payment` দিয়ে আবার মিলিয়ে নিন।
- ওয়েব পেজে `Strict-Transport-Security` ও `Content-Security-Policy` আছে। স্ক্রিপ্ট শুধু নিজের সাইট (আর Next.js-এর inline স্ক্রিপ্ট) ও Cloudflare Turnstile থেকে চলে। ব্রাউজার থেকে ডেটা শুধু নিজের সাইট, API ও Cloudflare-এ যেতে পারে। কেউ কোনোভাবে স্ক্রিপ্ট ঢুকিয়ে দিলেও সেটা অন্য সাইট থেকে কোড আনতে বা লগইন টোকেন অন্য সাইটে পাঠাতে পারবে না। `unsafe-inline` রাখতে হয়েছে কারণ Next.js নিজে ছোট inline স্ক্রিপ্ট লেখে।
- সার্ভারের হাল দেখতে `sudo bash deploy/ubuntu/audit-server.sh` (কিছু বদলায় না, শুধু দেখায়): `.env`-এর পারমিশন, খোলা পোর্ট, ফায়ারওয়াল, SSH, fail2ban, সিকিউরিটি আপডেট, ব্যাকআপ ফোল্ডার, HTTPS, সার্টিফিকেটের মেয়াদ। প্রতিটা `WARN` ঠিক করে আবার চালান। aaPanel-এ দুই সাইটেই **Force HTTPS** চালু রাখুন, নইলে `http://` সরাসরি খোলে।
- `update.sh` শুধু কোড টানে। `deploy/ubuntu/` এর nginx snippet ও systemd ফাইল বদলালে সার্ভারে আলাদা করে বসাতে হয়: nginx snippet aaPanel-এর সাইট কনফিগে বসিয়ে রিলোড, আর systemd ফাইল `sudo install -m 644 deploy/ubuntu/uniqpay-*.service /etc/systemd/system/ && sudo systemctl daemon-reload && sudo systemctl restart uniqpay-api uniqpay-web`।
